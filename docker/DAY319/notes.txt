Day 319 - Port Forwarding & Networking Basics

Topic Overview:
Containers run inside their own isolated network namespace with private IP addresses (e.g. `172.17.0.2`).
If you run an Nginx or Express server inside a container on port 80 or 3000, your Mac browser CANNOT reach it directly through `localhost:80` unless you explicitly publish/forward the port!

Port Forwarding Syntax:
`-p <HOST_PORT>:<CONTAINER_PORT>`
Example: `-p 8080:80`
- `HOST_PORT` (8080): The port on your host machine (Mac/laptop). You visit `http://localhost:8080`.
- `CONTAINER_PORT` (80): The internal port your application or Nginx is listening to inside the container.

Docker bridges the host port to the container port via `iptables` / virtual network socket routing.

Keep an eye on:
- Host port conflicts: If host port 8080 is already in use by another app on your machine, Docker will fail with `bind: address already in use`. Just switch host port: `-p 8081:80`.
- Inside the container, Express or Nginx MUST bind to `0.0.0.0` (all network interfaces), NOT `127.0.0.1` (localhost)! If your server listens only on `127.0.0.1` inside the container, requests forwarded from the host will be rejected.
