Day 324 - Container Volumes & Persistent Data: Part 2 (Named Volumes)

Topic Overview:
Yesterday we covered Bind Mounts for development code. Today we covered Named Volumes for databases and persistent production data.
If you run a PostgreSQL or MongoDB container and insert 10,000 user records, what happens when you stop and remove the container (`docker rm -f pg-db`)?
All your data is DELETED! Because the container writable layer is destroyed.

Named Volumes to the Rescue:
Docker Named Volumes are completely managed by Docker in a dedicated storage directory on the host (`/var/lib/docker/volumes/`).
They exist independently of the container lifecycle:
- Even if the container crashes or is deleted, the volume remains intact.
- A new container can be attached to the exact same volume to immediately recover all data!

Commands:
- `docker volume create <vol_name>`
- `docker volume ls`
- `docker volume inspect <vol_name>`
- `docker volume rm <vol_name>`
- Mounting in run: `-v <volume_name>:<container_data_dir>`
  e.g. `-v pg_bengaluru_data:/var/lib/postgresql/data`

Keep an eye on:
- Never store database data directly inside the container's writable layer without a volume.
- Named volumes are much faster than bind mounts on macOS and Windows because they avoid host filesystem translation overhead.
